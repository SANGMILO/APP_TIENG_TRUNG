# Video Learning Architecture

## Overview

The video learning system enables Chinese language learning through interactive video content with clickable subtitles, inline questions, and vocabulary integration.

## Data Flow

```
Admin uploads → Storage (private bucket) → videos table (metadata)
                                         → video_subtitles (cues)
                                         → video_questions (interactive)

Student watches → signed URL from backend
               → subtitle overlay from DB
               → questions trigger on timestamp
               → progress saved periodically
               → vocabulary saved on click
               → XP on completion
```

## Database Schema

```
videos (1) ──── (N) video_subtitles
videos (1) ──── (N) video_questions
videos (1) ──── (N) video_vocabulary
videos (1) ──── (N) user_video_progress
video_questions (1) ── (N) video_question_options
video_questions (1) ── (N) user_video_question_attempts
```

## Storage Strategy

### Buckets
- `video-content` (private) — Video files
- `video-thumbnails` (public or private) — Thumbnail images

### Object Paths
```
video-content/{video_id}/original.mp4
video-content/{video_id}/playback.mp4
video-thumbnails/{video_id}/thumb.jpg
```

### Access Control
- Student: Read via signed URL (generated by Edge Function after entitlement check)
- Editor/Admin: Upload/manage via admin interface

### Signed URL Flow
```
1. Client requests playback → Edge Function
2. Function checks: user authenticated? video published? premium entitlement?
3. Function generates short-lived signed URL (e.g., 1 hour)
4. Client uses signed URL for video source
5. On expiry → client requests new URL
```

## Subtitle System

### Storage Format
Each subtitle cue is a database row with:
- `start_ms` / `end_ms` — Timing in milliseconds
- `chinese_text` — Original Chinese
- `pinyin` — Pinyin romanization
- `vietnamese_text` — Vietnamese translation
- `sequence` — Display order

### Lookup Algorithm
Binary search on sorted cues array:
```typescript
function findCurrentCue(cues, timeMs) {
  // O(log n) binary search
  // Returns cue where start_ms <= timeMs < end_ms
}
```

### Import
Supports SRT format parsing:
```
1
00:00:00,000 --> 00:00:03,000
你好！
```

Admin can import Chinese SRT, then manually add Pinyin/Vietnamese.

## Chinese Tokenization

### Algorithm
Forward Maximum Matching (FMM):
1. From position i, check if text[i..i+maxLen] exists in dictionary
2. If yes → emit token, advance by matched length
3. If no → reduce length, try again
4. If length=1 → emit single character token

### Dictionary
Built from published `vocabulary` table at runtime.
Cached via TanStack Query.

### Future Upgrade Path
Replace with:
- jieba backend (Edge Function)
- NLP segmentation service
- AI-powered tokenization

## Interactive Questions

### Trigger Logic
```
On time update:
  if (pending question exists at timestamp <= currentTime)
    AND (question not already answered in this session):
      pause video
      show question overlay
      wait for answer
      resume video
```

### Seek Protection
Required questions between seek start and seek end are still triggered.

## Progress Tracking

### Save Strategy
- Periodic: every 15 seconds during playback
- Event-based: pause, unmount, route change
- Completion: when progress >= 90% AND required questions done

### Watch Time
Only actual playing time counts. Paused/background time excluded.
Seek jumps don't add to watch time.

## XP Reward

- `complete_video()` PostgreSQL function
- Idempotency: `{user_id}:video_complete:{video_id}`
- One XP reward per video per lifetime
- Configurable per video (`xp_reward` column)

## Premium Content

```
is_premium = true → check subscription/entitlement
is_premium = false → available to all authenticated users
```

Frontend lock is visual only. Backend enforces via signed URL generation.
